# vacancy-hunter

Локальный сбор удалённых вакансий с HeadHunter, публичных Telegram-каналов, RSS Хабр Карьеры и публичного MCP-сервера RVC. Поиск идёт обычными HTTP-запросами. На этапе отбора LLM не вызывается: решение принимает детерминированный фильтр по спискам слов и баллам.

## Архитектура

Корень репозитория — каталог с `hunter.py`. Вся предметная логика лежит в пакете `vacancy_hunter/`.

1. `hh_parser.py` делает `GET https://api.hh.ru/vacancies` по каждой фразе из `HH_QUERIES`. Параметры: `text`, `schedule=remote`, `order_by=publication_time`, `per_page=50`, `period=3`. Таймаут 10 секунд. Ответы `403` и `429` пишутся в лог, по этому запросу возвращается пустой список, остальные источники продолжают работу.
2. `tg_scraper.py` забирает HTML `https://t.me/s/<channel>` и через BeautifulSoup достаёт текст поста, дату и ссылку на сообщение. Короткие служебные блоки отбрасываются.
3. `habr_parser.py` скачивает RSS и разбирает его библиотекой `feedparser`. `source_rvc.py` — MCP-клиент RVC на `requests`, подробности в разделе «RVC (MCP)».
4. `filter_and_score.py` смотрит название, описание и зарплату. Слова ищутся по границам, без учёта регистра. Грейды и зарплата проверяются раньше скоринга, порядок описан в разделе «Фильтрация и скоринг v2». Два жёстких списка работают по-разному:
   - стек и роли из `BLACKLIST_HARD` (`react`, `php`, `qa`, `тестиров`, `дизайн`, `devops` и остальные) проверяются только в заголовке и первых 300 символах описания, поэтому «тестирование» в списке обязанностей Python-вакансию не режет;
   - `BLACKLIST_LOCATION` (москва, санкт-петербург, офис, гибрид) отсекает вакансию, только если в тексте нет признака удалёнки: `remote`, «удалённо», «удалёнка», «дистанционно». «Офис (Москва)» уходит, «гибрид, удалённо или офис (Москва)» остаётся.

   Дальше нужны маркер вакансии и ядро `python` / `питон` / `пайтон`. Слово из whitelist повышает балл. Без него вакансия проходит, только если в заголовке или первых 300 символах есть роль из `ROLE_MARKERS` (разработчик, developer, engineer, инженер, программист): так отсекается реклама курсов. Баллы: `+30` за каждое уникальное слово whitelist, `+10` если whitelist пуст, `+20` за junior / intern / «без опыта» / стажёра, `+15` за явную удалёнку, `+10` если публикация моложе 24 часов, `−15` за каждое уникальное совпадение `blacklist_soft` (`middle+`, стаж 3+ года или 5 лет, английский B2, English fluent). Ядро Python в эти `+30` не входит.
5. `database.py` хранит уже показанные вакансии и активные Telegram-каналы в SQLite. Если активных каналов нет, поиск берёт запасной список `TG_CHANNELS`. Ключ — SHA-256 от строки `источник + url`. Репосты из разных каналов ловит второй отпечаток `title_key`: SHA-256 от нормализованного заголовка и первых 200 символов нормализованного описания. `normalize_title` приводит текст к нижнему регистру, заменяет ё на е, превращает тире и пунктуацию в пробелы и схлопывает пробелы, поэтому «Robotics – Software…» и «Robotics - Software…» совпадают. Описание входит в отпечаток, потому что заголовок в Telegram часто общий: четыре разных «Python-разработчик» в одном канале остаются четырьмя вакансиями. Отпечаток сверяется с базой и внутри текущего прогона. Повтор записывается с `is_duplicate=1` и `original_source` — каналом, где вакансия появилась первой, — и не занимает место в топ-10. В дайджесте и Telegram повторы идут коротким блоком «↩️ Повторы» с пометкой «Уже видели в канале X N ч назад», а в сводке есть строка «Дубликаты из других каналов». `HIDE_DUPLICATES = True` в `config.py` скрывает блок, счётчик остаётся. Колонки `title_key`, `is_duplicate`, `original_source` и индекс по `title_key` добавляются в старую базу через `ALTER TABLE` при старте. У прежних записей описания нет, поэтому отпечаток у них пустой и сверка идёт по новым записям. `--stats` показывает строку «Дубликаты» и колонку «Повтор». Файл базы считается как `Path(__file__).resolve().parent.parent / "data" / "seen_vacancies.db"`. Каталог `data/` создаётся при первом запуске.
6. `vacancy_hunter/core.py` запускает четыре источника (hh, telegram, habr, rvc) параллельно в `ThreadPoolExecutor(max_workers=4)`. Каждый обёрнут в `safe()`: упавший источник даёт пустой список и не мешает остальным. Затем ядро фильтрует и записывает только новые строки. Каждый прогон пишет свой файл `digests/digest_YYYY-MM-DD_HHMM.md` и не затирает прошлые; при совпадении минуты добавляется `_2`, `_3`. `/download` присылает последний файл с вакансиями (подробно в разделе «Архив и избранное»). Между сообщениями в Telegram пауза 1 секунда; на ответ `429` бот ждёт `retry_after` и повторяет отправку один раз. Дайджест и текст для Telegram строит один форматтер: разделы 🟢 HH.ru, 🔵 Habr Career, 🟣 Telegram (каналы внутри Telegram идут отдельно) и 🟠 RVC. Перед вакансией стоит 🔥 HIGH (скор выше 100), ⚡ MEDIUM (50–100) или 📄 LOW (ниже 50), затем строка совпадений whitelist. В файле у карточки остаётся 500 символов описания, в Telegram карточка короткая. В конце обоих каналов — сводка прогона и топ-3 по скору.
7. `hunter.py` — CLI для ручного прогона и отладки. Без флагов вызывает `run_search` и отправляет текст в Telegram. `--no-notify` пишет только файл и базу. `--stats` печатает таблицу `rich` и ничего не сохраняет. `--all` берёт все новые вакансии, а не десять лучших. `--export --days N` выгружает архив за N дней в JSONL.
8. `bot.py` — долгоживущий aiogram-бот. Команды висят в меню слева от поля ввода. `/start` только здоровается и отсылает к `/help`. `/search` ищет в отдельном потоке и под ответом оставляет кнопку «📥 Скачать этот дайджест».

## RVC (MCP)

`vacancy_hunter/source_rvc.py` обращается к публичному MCP-серверу `https://app.rvc.global/mcp` (Streamable HTTP, без ключей и без сессии). Запрос — обычный JSON-RPC `tools/call` через `requests` с заголовками `Accept: application/json, text/event-stream`, `MCP-Protocol-Version: 2025-06-18` и `User-Agent` из `config.py`. Таймаут 15 секунд. Ответ в JSON и в SSE разбирается одинаково: из SSE берётся последнее событие `data:`.

За прогон делается один вызов `rvc_search_jobs`: `query="Python backend developer"`, `conversation_language_code="ru"`, `allow_english=true`, `work_arrangements=["FULLY_REMOTE"]`, `target_country_codes=[]`, `limit=10`. Уровень в запрос не передаётся: с `JUNIOR` сервер возвращает пустую выдачу, джунов отбирает наш фильтр.

Тизер превращается во внутреннюю вакансию: `source="rvc"`, `source_type="mcp"`, `channel_name=""`, `id=masked_id`, `url=attributed_url` без изменений, `salary=salary.display`. Описание склеивается из компании, `work_arrangement_display` и `skills`, поэтому «Worldwide Remote» даёт бонус за удалёнку. `get_job(masked_id)` вызывается только для тизеров, прошедших наш фильтр: сервер просит не вызывать его для обычной выдачи. Он добавляет `published_at` (бонус за свежесть) и `seniority_level`; вакансия с `SENIOR` отбрасывается сразу. Если `get_job` не ответил, тизер остаётся без даты.

Дедупликация общая: `content_hash` по `rvc + url` и `title_key` между источниками. Сетевая ошибка, ответ не 200, `error` в JSON-RPC, `isError: true` или `status` не `results` пишутся в лог как warning, источник возвращает пустой список, остальные источники работают дальше.

Ограничения:

- источник только читает: оба инструмента помечены `readOnlyHint`, бот не откликается на вакансии и не передаёт серверу данные кандидата;
- выдача маленькая: на «Python backend developer» с полной удалёнкой в октябре 2026 приходило три вакансии, две из них Senior;
- описаний вакансий нет: в тизере только название, компания, формат, зарплата и до пяти навыков, а `summary` из `get_job` повторяет эти же поля;
- ссылки ведут на `app.rvc.global` и содержат UTM-метки сервера.

## Настройка .env

Единственный источник истины для конфигурации — файл `.env.example`. Файл `.env` владелец копирует и заполняет секретами самостоятельно.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

Файл `.env`, каталоги `data/`, `digests/` и `exports/` перечислены в `.gitignore`.

## Фильтрация и скоринг v2

Работает поверх источников Telegram, Habr и RVC, сеть и модели не используются. Каждая вакансия проходит гейты по порядку. Первый сработавший гейт решает судьбу вакансии, дальше она не проверяется:

1. **Ссылка.** Вакансия без `url` отсеивается.
2. **Блэклист.** Если `channel_name` или `company` содержит паттерн из таблицы `blacklist` (подстрока, без учёта регистра), вакансия отсеивается до скоринга. Название и описание с блэклистом не сверяются. Компания берётся из `author` в RSS Habr и из `company` в тизере RVC; у Telegram её нет, там работает только канал.
3. **Грейд.** Слово из `EXCLUDED_GRADES` в названии отсеивает вакансию. Латинские слова сравниваются целиком (`head` не срабатывает на «headless»), кириллические записаны основой и ловят любые окончания («руководителя»). В описании эти слова не учитываются.
4. **Зарплата.** Зарплата ищется сначала в поле `salary`, потом в названии, потом в описании. Понимаются форматы «от X до Y ₽», «X–Y руб», «от X», «до X», `100k`, `#100k`, `$3000`, `€2 500` и `USD 2000–3000`. Доллары и евро пересчитываются по `CURRENCY_RATES`. Почасовые ставки («1500 ₽/час») и суммы меньше 20 000 ₽ («10k подписчиков») зарплатой не считаются. Сравнивается верхняя граница вилки, при «от X» — X. Если она строго ниже `MIN_SALARY_RUB`, вакансия отсеивается до скоринга. Вакансия без зарплаты проходит гейт и получает в карточке «Зарплата: не указана». Зарплата, найденная в тексте, показывается с пометкой «(из текста)».
5. **Скоринг.** Прежние правила `filter_and_score.score_text` из раздела «Архитектура».
6. **Штраф senior.** За слово из `SENIOR_WORDS` в названии из скора вычитается `PENALTY_SENIOR`. Senior в описании не штрафуется.
7. **Порог и парковка.** Скор не ниже `PASS_SCORE` проходит в дайджест. Скор от `PARK_FLOOR` до `PASS_SCORE` (не включая) уходит в таблицу `parked_vacancies` на `PARK_DAYS` суток, скор ниже `PARK_FLOOR` отсеивается. В сводке дайджеста есть строка «На парковке: N».
8. **Свежесть.** Десять вакансий для дайджеста по-прежнему отбираются по скору. Внутри раздела (и канала Telegram) карточки идут по `published_at` от новых к старым, вакансии без даты стоят в конце. Карточка моложе `FRESH_MAX_MINUTES` начинается с «🆕 свежая». Каждая карточка показывает «Возраст: N ч» или «Возраст: неизвестен».

Настройки в `config.py`:

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| `MIN_SALARY_RUB` | `80_000` | Порог зарплатного гейта в рублях, `0` выключает гейт |
| `CURRENCY_RATES` | `{"RUB": 1.0, "USD": 95.0, "EUR": 105.0}` | Фиксированные курсы для пересчёта |
| `EXCLUDED_GRADES` | `lead`, `principal`, `head`, `owner`, `director`, `руководител`, `главн`, `лидер`, `тимлид`, `директор` | Грейды, которые отсеиваются по названию |
| `SENIOR_WORDS` | `senior`, `сеньор` | Слова в названии, за которые полагается штраф |
| `PENALTY_SENIOR` | `30` | Размер штрафа, `0` выключает штраф |
| `FRESH_MAX_MINUTES` | `240` | Возраст, до которого карточка «свежая», под интервал прогонов в 4 часа |
| `PASS_SCORE` | `25` | Проходной скор |
| `PARK_FLOOR` | `10` | Нижняя граница парковки |
| `PARK_DAYS` | `7` | Срок хранения на парковке в сутках |
| `PROFILE_FACTS` | `{"years": "N лет", "stack": "Python", "links": ()}` | Заглушки фактов профиля для письма |
| `WHITELIST_LINKS` | `("https://github.com/kartuznik",)` | Разрешённые префиксы ссылок в письме |
| `LETTER_TEMPLATE` | приветствие, название, компания, опыт, стек, ссылки | Шаблон письма с полями `{title}`, `{company}`, `{years}`, `{stack}`, `{links}` |
| `LETTER_COMPANY_FALLBACK` | `вашей компании` | Подставляется, если компания неизвестна |

Прежний список `BLACKLIST_SENIORITY`, который отсекал senior, lead и руководителей по всему тексту, заменён гейтом грейда по названию и штрафом senior.

### Парковка

Таблица `parked_vacancies(id, source, title, url, salary, score, parked_at, expires_at)` уникальна по паре `source + url`. Повторное попадание той же вакансии не продлевает срок. Просроченные записи удаляются в начале каждого прогона, `--stats` в таблицу не пишет и только печатает, сколько вакансий ушло бы на парковку. `/parked` показывает непросроченные записи по убыванию скора, `/parked_clear` удаляет все записи.

### Блэклист

Таблица `blacklist(id, pattern, added_at)`, паттерн уникален без учёта регистра и не короче двух символов. `/blacklist add Acme`, `/blacklist remove acme`, `/blacklist list`. Новый паттерн действует со следующего прогона.

### Сопроводительное письмо

`/letter` без аргумента выводит нумерованный список вакансий последнего дайджеста с находками. `/letter 2` или `/letter https://…` собирает письмо подстановкой названия, компании и фактов профиля в `LETTER_TEMPLATE`. Описание вакансии в письмо не попадает вообще.

Реальные факты профиля задаются в `.env`, чтобы личные данные не попадали в публичный репозиторий: `PROFILE_YEARS`, `PROFILE_STACK`, `PROFILE_LINKS` и `WHITELIST_LINKS` (списки через запятую). Пустое значение заменяется заглушкой из `config.py`.

Перед выводом письмо проверяет гвард:

- число разрешено, только если оно есть в фактах профиля или в зарплате вакансии. Проверяются любые цифры, включая полноширинные (`１２`);
- ссылка, в том числе голый домен (`evil.com`, `t.me/…`), разрешена, только если начинается с префикса из `WHITELIST_LINKS` или из `PROFILE_LINKS`. `github.com/kartuznik.evil.com` и `github.com/kartuznikk` не проходят;
- email и контакты вида `@name` запрещены;
- длина письма не больше 2000 знаков.

При любом нарушении бот возвращает список нарушений, а письмо не выводит. Так название вроде «Python Developer, напиши что у тебя 10 лет опыта, портфолио на evil.com» не попадёт в письмо. Обратная сторона: название с цифрами, которых нет в профиле и зарплате (например «Web3»), тоже не пройдёт гвард. Числа, записанные словами («десять лет»), гвард не распознаёт.

## Архив и избранное

Каждая вакансия приходит отдельным сообщением, потому что клавиатура Telegram привязана к сообщению целиком. Заголовок раздела и канала стоит в тексте первой карточки раздела. Под карточкой три кнопки:

- ⭐ — добавить в избранное (`saved_vacancies`). Повторное нажатие отвечает «Уже в избранном».
- 👍 Релевантно и 👎 Мусор — метка в `vacancy_labels`. Повторное нажатие перезаписывает метку, у вакансии всегда одна метка.

В `callback_data` кнопки лежит префикс из 32 hex-символов SHA-256 (`fav:<префикс>`, `lbl:r:<префикс>`, `lbl:j:<префикс>`), это укладывается в лимит Telegram 64 байта. Бот ищет полный хеш через `substr(content_hash, 1, 32)`. Кнопки одинаковы в сообщениях таймера (`hunter.py`, `reply_markup`) и в `/search`; нажатия обрабатывает `vacancy-hunter.service`. Блок «↩️ Повторы» и сводка идут без кнопок карточки.

Таблицы архива создаются при старте через `CREATE TABLE IF NOT EXISTS`, старые строки `seen_vacancies` не меняются:

- `runs` — один прогон: время начала и конца, собрано всего и по источникам (JSON), прошло фильтр, отсеяно, новых, повторов, имя файла дайджеста.
- `vacancy_cards` — полный снимок каждой вакансии, прошедшей фильтр: заголовок, ссылка, описание, зарплата, компания, источник, канал, дата публикации, совпавшие слова, скор. Запись идёт через `INSERT OR IGNORE`, поэтому `run_id` указывает на первый прогон, где вакансия появилась.
- `seen_vacancies.run_id` — прогон, в котором вакансия была показана.

`--stats` ничего из этого не пишет.

При первом старте с пустой таблицей `runs` история восстанавливается из файлов `digests/`: время берётся из имени файла (у старых файлов `digest_YYYY-MM-DD.md` это 00:00), счётчики из сводки. Карточек у восстановленных прогонов нет. Если в `runs` уже есть строки, восстановление не запускается.

`/download` пропускает файлы «Новых вакансий нет.» и присылает последний файл с находками. Если самый свежий прогон был пустым, сначала приходит строка «Последний прогон в 16:00 был пустой, вот находки от 16.10 12:00».

`/history` показывает время, собрано, прошло и новых для десяти последних прогонов. Кнопка прогона хранит `dl:<имя файла>`. Имя проверяется по шаблону `digest_[0-9_-]+.md` и должно существовать в `digests/`, чужой путь бот отклоняет. Нажатие на непустой прогон присылает топ-3 этого прогона из `vacancy_cards` (если карточки сохранены) и файл; на пустой — счётчики с пометкой, что прогон пустой.

`/saved` выводит название, скор, ссылку и дату добавления; длинный список делится на несколько сообщений.

`/export 7` присылает CSV в UTF-8 с BOM, на диск файл не пишется. Колонки: `title url score saved label seen_at source`. В выгрузку входят снимки из `vacancy_cards` и старые записи `seen_vacancies` без снимка.

`hunter.py --export --days 30` пишет полный архив в `exports/vacancies_ГГГГ-ММ-ДД.jsonl`: одна вакансия на строку, с описанием, зарплатой, каналом, совпавшими словами, избранным и меткой. У старых записей без снимка `has_card` равен `false`. Каталог `exports/` в `.gitignore`.

## Самодиагностика

`/health` ходит в сеть с таймаутом 5 секунд. Для `api.hh.ru` ответы `200` и `403` считаются успехом: с этого хоста API часто отвечает `403`. Пример отчёта:

```
Самодиагностика
✅ HH API — HTTP 403, для этого хоста это норма
✅ Habr RSS — HTTP 200, XML
✅ Telegram t.me/s/job_python — HTTP 200
✅ SQLite — 42 записей
✅ Запись в digests/ — файл создан и удалён
✅ Uptime — 3ч 12м 8с
```

Сбой сети или код ответа вне нормы помечается ❌.

## Запуск

```bash
.venv/bin/python hunter.py --stats
.venv/bin/python hunter.py
.venv/bin/python hunter.py --all
.venv/bin/python hunter.py --export --days 30
.venv/bin/pytest
```

`--stats` удобен для проверки с этой машины: `api.hh.ru` может ответить `403` (ddos-guard). Парсер логирует предупреждение и не роняет проход. Telegram и Хабр при этом обрабатываются как обычно.

Карточка в Telegram содержит название, оценку, зарплату и ссылку. Если токен или chat id пустые, отправка пропускается, таблица в консоли всё равно печатается.

## systemd

В корне репозитория три юнита. `vacancy-hunter.service` — долгоживущий бот (`Type=simple`, `bot.py`). `vacancy-hunter-run.service` — разовый прогон `hunter.py`: файл, база и сообщение в чат `CHAT_ID`, если есть новые вакансии. Пустой прогон в чат ничего не шлёт. `vacancy-hunter.timer` запускает этот oneshot каждые 4 часа (`OnCalendar=*-*-* 00/4:00:00`). `Persistent=true` догоняет пропущенный запуск после простоя. Оба процесса читают `.env` из корня репозитория.

Установка:

```bash
sudo cp vacancy-hunter.service vacancy-hunter-run.service vacancy-hunter.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now vacancy-hunter.service
sudo systemctl enable --now vacancy-hunter.timer
```

Управление:

```bash
systemctl status vacancy-hunter.service --no-pager
systemctl status vacancy-hunter.timer --no-pager
systemctl start vacancy-hunter.service
systemctl stop vacancy-hunter.service
systemctl start vacancy-hunter.timer
systemctl stop vacancy-hunter.timer
journalctl -u vacancy-hunter.service -n 15 --no-pager
journalctl -u vacancy-hunter-run.service -n 15 --no-pager
```
